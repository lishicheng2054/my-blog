# Mizuki 中英双语与顶部语言切换设计

## 目标

在保持 Mizuki 原有导航栏视觉语言的前提下，增加一个位于顶部工具栏的语言切换按钮，并让站点界面、文章元数据和文章正文都具备对应的中英文版本。

首期完整支持：

- 简体中文：`zh_CN`，公开路径前缀 `/zh/`
- English：`en`，公开路径前缀 `/en/`

架构预留 `zh_TW` 和 `ja`，但首期不生成繁体中文和日语正文。

## 用户体验

### 顶部按钮

采用已确认的 B 方案：

- 位于“显示设置”与“主题切换”之间。
- 外层复用现有 `btn-plain scale-animation rounded-lg` 控件语言。
- 点击区域不小于 `44 × 44px`。
- 按钮包含 Material Symbols 地球图标、当前语言短标签和下拉箭头。
- 中文显示“中”，英文显示“EN”。
- 默认背景与相邻按钮保持一致；悬停、展开和键盘聚焦时使用主题色半透明背景。
- 使用现有 CSS 变量，不硬编码与主题冲突的颜色。

### 下拉菜单

- 菜单复用 `float-panel` 的毛玻璃、阴影、边框和暗色模式。
- 每个语言项展示本地语言名称，例如“简体中文”和“English”。
- 当前语言使用主题色背景、勾选图标和 `aria-current` 标识。
- 点击外部、按 `Escape` 或选择语言后关闭。
- 支持键盘 Tab、Enter 和 Space 操作。
- 移动端保持在顶部栏中；必要时只显示短标签，不隐藏切换能力。

### 切换行为

- 切换普通页面时，保留当前相对路径，只替换语言前缀。
- 切换文章页时，跳转到同一 `translationKey` 的目标语言文章。
- 保存用户选择到 `localStorage`。
- 首次访问根路径时，优先读取已保存语言；没有记录时默认进入简体中文站点。
- 如果目标文章没有对应译文，该语言项显示不可用状态，并提示“暂无该语言版本”，不跳转到不存在的页面。

## 多语言架构

### 静态多版本构建

保留 Astro 静态站点模式，分别构建中文和英文版本：

1. 中文构建使用 `SITE_LANG=zh_CN` 和 `SITE_BASE=/zh/`。
2. 英文构建使用 `SITE_LANG=en` 和 `SITE_BASE=/en/`。
3. 构建脚本把两个版本合并到最终 `dist/zh/` 与 `dist/en/`。
4. 根目录生成轻量入口页，根据已保存语言跳转，默认跳转 `/zh/`。

这种方式让现有 `i18n()` 在每次构建中继续使用固定语言，避免在浏览器中扫描和替换 DOM，也避免静态 HTML 首屏出现语言闪烁。

### 站点配置

`siteConfig.lang` 从构建环境读取，并通过允许列表校验。没有提供环境变量时继续使用当前配置值，保证单语言开发模式仍然可用。

语言配置集中定义：

- 语言代码
- URL 前缀
- 本地名称
- 顶部按钮短标签
- 是否启用

新增语言时只需扩展配置、翻译资源和文章内容，不修改按钮组件逻辑。

### 文章组织

文章按语言目录存放，并保持相同的相对文件名：

```text
src/content/posts/
├── en/
│   ├── markdown-tutorial.md
│   └── guide/index.md
└── zh_CN/
    ├── markdown-tutorial.md
    └── guide/index.md
```

每个语言版本包含：

```yaml
lang: en
translationKey: markdown-tutorial
```

或：

```yaml
lang: zh_CN
translationKey: markdown-tutorial
```

`translationKey` 在不同语言之间保持一致。标题、描述、标签、分类和正文分别翻译；发布日期、封面、作者、来源、加密设置等共享字段保持一致。

首期迁移并翻译当前 7 个 Markdown 文章文件，包括草稿。代码块、URL、图片引用、HTML 嵌入、Mermaid 语法和配置字段不翻译。

### 内容过滤

每次语言构建只读取当前语言文章：

- 首页文章列表只显示当前语言版本。
- 分类、标签、归档、随机文章和相关文章只使用当前语言集合。
- 搜索索引只包含当前语言标题与正文。
- RSS、Atom 和站点地图按语言分别生成。
- 前后篇文章导航只链接同语言内容。

## 路由与链接

公开路径使用统一的语言前缀：

```text
/zh/
/zh/posts/markdown-tutorial/
/zh/about/

/en/
/en/posts/markdown-tutorial/
/en/about/
```

内部链接通过语言感知的 URL 工具生成，避免组件中手写 `/zh/` 或 `/en/`。文章语言切换使用 `translationKey` 和构建时生成的文章映射，不依赖标题匹配。

根路径 `/` 仅负责语言选择和跳转，不承载重复内容。每个语言页面设置正确的：

- `<html lang>`
- canonical URL
- `hreflang="zh-CN"`
- `hreflang="en"`
- Open Graph locale
- 结构化数据 `inLanguage`

## 组件边界

### `LanguageSwitch.svelte`

职责：

- 渲染 B 方案按钮和下拉菜单。
- 读取当前构建语言。
- 获取当前页面可用语言目标。
- 处理菜单状态、键盘操作、焦点恢复和外部点击。
- 保存用户语言偏好并执行导航。

组件不负责翻译正文，也不直接读取 Markdown 文件。

### 语言配置模块

职责：

- 定义语言元数据和启用顺序。
- 规范化语言代码。
- 生成语言前缀和目标 URL。
- 为构建脚本与客户端组件提供同一份类型安全配置。

### 文章翻译映射

职责：

- 根据 `translationKey` 建立语言版本映射。
- 在构建时校验重复键、缺少语言和无效语言代码。
- 为文章页提供目标译文 URL。

## 状态与数据流

1. 构建脚本选择当前语言和路径前缀。
2. 内容层过滤当前语言文章。
3. Astro 按当前语言生成完整静态页面。
4. 页面把当前语言和可用译文 URL 传给 `LanguageSwitch`。
5. 用户选择语言后，组件保存偏好并导航到目标静态页面。
6. 新页面由目标语言构建产物直接提供，不做客户端正文翻译。

## 异常处理

- 无效的构建语言：构建立即失败，并列出允许值。
- 重复 `translationKey + lang`：构建失败，避免覆盖文章。
- 缺少目标译文：菜单项禁用并显示提示。
- 保存语言偏好失败：继续导航，不阻塞用户操作。
- 当前路径没有等价页面：跳转到目标语言首页。
- JavaScript 被禁用：语言菜单仍提供普通链接完成切换。

## 内容翻译规则

- 保留 Markdown 层级、锚点结构和列表结构。
- 标题锚点尽量保持跨语言稳定，必要时显式指定 ID。
- 不翻译代码、命令、文件名、URL、包名和 API 标识符。
- Mermaid 节点中的说明文字可以翻译，但语法关键字保持不变。
- 图片替代文本和说明文字需要翻译。
- 技术术语首次出现时可保留英文原词。
- 加密文章的密码和密码提示不自动改变，除非内容明确要求。

## 测试与验收

### 单元测试

- 语言代码规范化。
- 路径前缀替换。
- `translationKey` 映射。
- 缺失译文回退。
- 无效或重复文章语言配置校验。

### 构建测试

- 中文与英文构建均通过类型检查。
- 最终产物同时存在 `/zh/` 和 `/en/`。
- 每个已发布文章在两种语言下都有对应页面。
- 搜索、RSS、归档和相关文章不混入另一语言内容。
- 构建产物不存在重复路径。

### 浏览器测试

- 桌面端与移动端都能打开语言菜单。
- 亮色、暗色和滚动后的导航栏样式一致。
- 中文文章切换到英文后仍是同一 `translationKey`。
- 英文文章切换到中文后路径和内容正确。
- 选择结果在刷新和再次访问时保留。
- 键盘操作、焦点样式和 `Escape` 关闭正常。
- `prefers-reduced-motion` 下不使用非必要动画。

## 不在首期范围

- 自动调用第三方翻译 API。
- 用户提交的评论内容翻译。
- 自动生成日语和繁体中文文章。
- 在同一个 HTML 页面中动态替换整篇正文。

## 完成标准

- B 方案按钮在导航栏中与原生控件视觉一致。
- 中英文界面、文章元数据和正文均有独立静态页面。
- 当前 7 个 Markdown 文件完成中英文版本迁移。
- 两种语言构建、类型检查和关键浏览器流程全部通过。
- 不产生 `404`、重复路由或语言混排。
